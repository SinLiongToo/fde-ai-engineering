更好的搜尋，並量出差別Better search, measured

機器人的回答品質，上限由搜尋決定：沒找到的段落，AI 不可能引用。這一章把入門篇 B4 的陽春搜尋改進兩次，而且每一次都用同一組測試題量出效果，不靠感覺。

Search sets the ceiling on answer quality: a passage that isn't found can't be cited. This chapter improves the basic search from B4 twice, and measures each step against the same test questions instead of going by feel.

三個版本Three versions

v1：數相同的片段count shared pieces

就是入門篇 B4 的做法。問題：「公司」「提供」這種到處都有的片段，和「特休」這種很有資訊量的片段，算一樣多分。所以「公司有提供免費午餐嗎？」會被配到設備那段。

The B4 approach. Problem: everywhere-pieces like 公司 (company) and 提供 (provide) score the same as informative ones like 特休 (annual leave). So "does the company provide free lunch?" gets matched to the equipment section.

v2：罕見的片段比較重要，加上門檻rare pieces matter more, plus a threshold

一個片段出現在越少段落裡，代表它越能區分段落，權重就越高（這個概念叫 IDF）。再加上一條規則：總分低於門檻就當作「找不到」，讓機器人誠實說手冊沒寫。

The fewer chunks a piece appears in, the better it distinguishes them, so it gets more weight (this idea is called IDF). Add one rule: if the total score is below a threshold, treat it as "not found" so the bot honestly says the handbook doesn't cover it.

v3：同義詞表a synonym table

員工會說「年假」「筆電」「在家上班」，手冊寫的是「特休」「筆記型電腦」「遠端工作」。最直接的做法是維護一張同義詞表，問題裡出現左邊的詞，就把右邊的詞也加進去搜尋：

Employees say 年假, 筆電 and 在家上班; the handbook says 特休, 筆記型電腦 and 遠端工作. The most direct fix is a synonym table: when a left-hand word appears in the question, add the right-hand word to the search:

只看總分，v1 和 v2 一樣是 11 題。但分類看就很清楚：

On the total alone, v1 and v2 tie at 11. Broken down by type, the picture is clear:

  • v2 解決了「亂配」（手冊沒寫的 3 題全對），但門檻也擋掉了一些分數不高的正確結果，同義詞題反而變差。這就是取捨：門檻越高，越不會亂答，但也越容易漏掉。
  • v3 補回了同義詞題，總分提升到 15。
  • 這就是為什麼要分類：如果只看總分，你會以為 v2 沒有用。
  • v2 fixes false matches (all 3 not-in-handbook questions pass), but the threshold also blocks some low-scoring correct results, so synonym questions get worse. That's the trade-off: a higher threshold means fewer wrong answers but more misses.
  • v3 wins back the synonym questions, lifting the total to 15.
  • This is why you tag questions: from the total alone you'd conclude v2 was useless.

問題Question為什麼找不到Why it fails
最晚幾點要到公司？手冊寫的是「核心工作時間為上午十點」，沒有任何相同的詞。這是「換句話說」，同義詞表也幫不上。The handbook says "core hours start at 10 a.m." with no words in common. It's a paraphrase, beyond any synonym table.
加班費怎麼算？只有「加班」兩個字相同，分數 2.16，低於門檻 3.0。門檻的代價。Only 加班 matches, scoring 2.16, below the 3.0 threshold. The cost of the threshold.
年假要提前多久講？同義詞讓「特休」被找到，但只有這一個片段相同，分數仍然不夠。The synonym finds 特休, but that's the only shared piece, so the score still falls short.

我們沒有為了讓這 3 題通過而修改題目或硬調參數。誠實的測試集應該反映真正的弱點。要解決「換句話說」，需要能理解意思的搜尋方法：embedding（向量）搜尋，並和關鍵字搜尋合併使用。這是進階篇第 05 章的主題。

We did not reword questions or force parameters to make these pass. An honest test set reflects real weaknesses. Paraphrases need search that understands meaning: embedding (vector) search, combined with keyword search. That's the subject of core chapter 05.

同義詞表的代價The cost of a synonym table

同義詞表簡單有效，但要有人維護：新的說法出現時要記得加，加錯了會造成新的誤配（例如把「電腦」對應到「筆記型電腦」，問「電腦密碼」時也會跑去設備那段）。把它當成一份需要測試保護的資料。

A synonym table is simple and effective, but someone must maintain it: new phrasings need adding, and bad entries create new mismatches (mapping 電腦 to 筆記型電腦 also pulls "computer password" questions toward the equipment section). Treat it as data that needs tests.

2. 提高分數門檻，最可能發生什麼？2. What most likely happens when you raise the score threshold?
門檻是「寧可不答」與「盡量回答」之間的取捨，要用測試集找到適合你場景的值。
The threshold trades "rather not answer" against "answer whenever possible"; use your test set to pick the right value for your situation.
