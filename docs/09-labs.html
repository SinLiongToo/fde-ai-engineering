延伸作業Extension exercises

  1. 允許「不知道」：在 risk_level 加入 UNKNOWN，並規定此時 findings 必須說明缺少什麼資訊。寫測試。
  2. 接上真正的 embedding 模型：實作 Embedder 介面（例如用 sentence-transformers 或任一 embedding API），傳給 HybridRetriever。重跑評測：semantic-oncall 應該會通過。確認沒有其他案例退步後，更新 baseline。
  3. 核准期限：在 Agent.resume 加入檢查，等待超過指定時間的核准一律拒絕，並寫測試。
  4. 你自己的測試集：把語料換成你工作領域的 10 份文件，寫 15 題測試案例，其中至少 3 題是權限案例、1 題是已知會失敗的案例。
  1. Allow "don't know": add UNKNOWN to risk_level, and require findings to state what information is missing in that case. Write tests.
  2. Plug in a real embedding model: implement the Embedder protocol (e.g. with sentence-transformers or any embedding API) and pass it to HybridRetriever. Re-run the evals: semantic-oncall should now pass. Once nothing else regressed, update the baseline.
  3. Approval expiry: make Agent.resume reject approvals that arrive after a configurable delay, with tests.
  4. Your own test set: replace the corpus with 10 documents from your domain and write 15 test cases, including at least 3 permission cases and 1 known failure.

練習 2：AI code reviewerLab 2: AI code reviewer

對應第 3、4 章。用 Python 的 ast 模組做確定性的靜態檢查（SQL injection、寫死的金鑰、缺少逾時、eval、在程式中 DROP TABLE），可以選擇加上 LLM 補充語意問題。重點在設計：LLM 只提出發現，分數與結論由程式計算；LLM 回報的行號不存在就丟棄。

Covers chapters 3 and 4. Deterministic static checks with Python's ast module (SQL injection, hard-coded secrets, missing timeouts, eval, DROP TABLE in app code), with an optional LLM pass for semantic issues. The point is the design: the LLM only proposes findings; score and verdict are computed in code, and findings on non-existent lines are dropped.

延伸作業Extension exercises

  1. 新增規則：偵測 subprocess.run(..., shell=True) 搭配非常數參數。先寫測試，包含「常數字串不應該被報告」的案例。
  2. 在你自己的程式庫上執行，記錄誤報，然後修正規則並把誤報寫成測試。
  3. 把 LLM 補充改成使用你偏好的 provider（例如第 4 章的 Claude 寫法），保持 validate_llm_issues 與 merge_issues 不變。
  1. Add a rule detecting subprocess.run(..., shell=True) with non-constant arguments. Write tests first, including "constant strings are not reported".
  2. Run it on your own codebase, record the false positives, then fix the rules and turn each false positive into a test.
  3. Switch the LLM pass to your preferred provider (e.g. the Claude pattern from chapter 4), leaving validate_llm_issues and merge_issues unchanged.

練習 3：MCP SRE 服務Lab 3: MCP SRE service

對應第 5、6、8 章。一個最小的 MCP server（stdio）與 client，加上一個「診斷 → 查 runbook → 提出修改 → 人工核准 → 執行 → 驗證」的 workflow。雲端環境是模擬的（cloud_sim.py），不會呼叫任何真正的 GCP API。

Covers chapters 5, 6 and 8. A minimal MCP server (stdio) and client, plus a "diagnose → search runbooks → propose change → human approval → apply → verify" workflow. The cloud is simulated (cloud_sim.py); no real GCP API is called.

範圍說明Scope

這個 server 只實作 MCP 的一小部分（initialize、tools/list、tools/call、ping），目的是讓你看懂協定本身。正式專案請使用官方的 MCP SDK，它會處理完整的協定、傳輸與相容性。

This server implements only a small part of MCP (initialize, tools/list, tools/call, ping) so you can see the protocol itself. For real projects use an official MCP SDK, which handles the full protocol, transports and compatibility.

關於證照About certifications

對 FDE 這類職位，證照的參考價值有限。比較有說服力的是：你做過、上線過、能講清楚取捨的系統，加上一份公開的作品或技術文章。如果客戶主要在某一家雲端平台上，該平台的架構類證照能幫你更快和客戶的基礎架構團隊建立共同語言，這是實際的用處。不要為了收集證照而犧牲做專案的時間。

For FDE-type roles, certifications carry limited weight. What persuades is systems you built and shipped and can explain the trade-offs of, plus public work or technical writing. If your customers mostly run on one cloud, that cloud's architecture certification helps you share vocabulary with their infrastructure teams faster; that is its practical value. Don't trade project time for collecting certificates.
