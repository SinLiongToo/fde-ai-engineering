API 是什麼What an API is

想像你在餐廳點餐：你（你的程式）把點餐單（請求）交給廚房（AI 服務），廚房做好後送回一道菜（回應）。你不需要知道廚房裡怎麼煮，只要知道點餐單要怎麼填。API 就是那張「點餐單的規則」：要寫哪些欄位、用什麼格式。

Picture ordering at a restaurant: you (your program) hand an order slip (the request) to the kitchen (the AI service), and the kitchen sends back a dish (the response). You don't need to know how the kitchen cooks, only how to fill in the slip. The API is the set of rules for that slip: which fields, in what format.

最重要的一件事：AI 不會記得你The most important fact: the AI doesn't remember you

一句話重點Key point

API 每一次請求都是獨立的。AI 不會記得上一次你問了什麼。聊天程式之所以「記得」，是因為它每次都把整段對話重新送一次。

Every API request is independent. The AI doesn't remember what you asked last time. Chat apps "remember" because they resend the whole conversation every time.

這帶來兩個結果：第一，如果你的程式忘了把之前的對話送出去，AI 就看不懂「它」「剛剛那個」指的是什麼。第二，對話越長，每次送出的內容越多，費用也越高。用下面的示範感受一下。

Two consequences follow. First, if your program forgets to send the earlier conversation, the AI can't tell what "it" or "that one" refers to. Second, the longer the conversation, the more you send each time, and the more it costs. Try it below.

API key：當成密碼加信用卡API keys: treat them like a password plus a credit card


要使用 AI 服務的 API，你需要一把 API key（一串很長的字）。它證明「這個請求是你送的」，而且費用會算在你頭上。如果被別人拿到，他們可以用你的帳號花你的錢。


To use an AI service's API you need an API key (a long string). It proves the request came from you, and the charges go to you. Anyone who gets it can spend your money from your account.



  絕對不要Never
  
把 API key 直接寫在程式碼裡，或上傳到 GitHub。網路上有程式專門在掃描公開的程式碼找 key。正確做法是放在環境變數裡，程式執行時再讀取。

  
Write an API key directly in your code or push it to GitHub. Bots scan public code looking for keys. Put it in an environment variable instead, and read it when the program runs.

  為什麼不是直接用 response.content[0]？Why not just response.content[0]?
  
很多舊教學會寫 response.content[0].text。較新的模型在回應裡可能先放其他類型的區塊（例如思考過程的區塊），第一個不一定是文字。只挑 type == "text" 的區塊比較安全。

  
Many older tutorials write response.content[0].text. Newer models may put other kinds of blocks (such as a thinking block) first, so the first block isn't necessarily text. Picking only blocks with type == "text" is safer.





小測驗Quiz



  

    1. 使用者先問「Python 是什麼？」，接著問「它難學嗎？」。第二次請求的 messages 應該包含？1. A user asks "What is Python?" then "Is it hard to learn?". The second request's messages should contain:
    
    
    
    
API 不會記得上一次的請求。沒有前文，AI 不知道「它」指的是 Python。

    
The API doesn't remember previous requests. Without the history, the AI can't know "it" means Python.

  

  

    2. API key 應該放在哪裡？2. Where should an API key live?
    
    
    
    
key 等於你的帳號與錢包。任何進到程式碼或 GitHub 的 key 都應該視為已經外洩，立刻作廢重發。

    
A key is your account and your wallet. Any key that reaches code or GitHub should be treated as leaked: revoke it and issue a new one.

  

  

    3. 一段對話聊了 50 輪，為什麼越後面的請求越貴？3. Why do later requests in a 50-turn chat cost more?
    
    
    
    
輸入的 token 也要付費。長對話常見的做法是只保留最近幾輪，或把舊的對話整理成摘要。

    
Input tokens are billed too. Long chats commonly keep only recent turns, or summarise older ones.
