為什麼要分這麼多檔案？因為每個部分會各自改變：換搜尋方法不該動到工具，改回答格式不該動到搜尋。分開之後，每個部分都可以單獨測試。

Why so many files? Because each part changes independently: swapping the search shouldn't touch the tools, and changing the answer format shouldn't touch the search. Separated, each part can be tested on its own.

設定集中在一個地方Keep settings in one place

每一個「上限」都是刻意的：AI 系統出問題時，常常不是當掉，而是「一直重試」或「一直呼叫工具」，帳單就這樣燒掉了。把上限寫在明顯的地方，是最便宜的保險。

Every limit is deliberate: when AI systems misbehave they rarely crash; they retry forever or call tools forever, and that's how bills explode. Putting limits somewhere obvious is the cheapest insurance there is.

把 AI 包成一個可替換的介面Wrap the AI in a swappable interface

機器人的其他程式只認得一個方法：llm.create(system, messages, tools, output_schema)，回傳一個 Reply。至於背後是誰在回答，它不在乎。

The rest of the bot knows exactly one method: llm.create(system, messages, tools, output_schema), which returns a Reply. It doesn't care who answers behind it.

為什麼需要假模型Why a fake model?

FakeLLM 不是 AI，它是一組固定的規則：從提供的手冊段落中挑最相近的一段引用、問到特休餘額就呼叫工具。它的用途是：

FakeLLM isn't AI. It's a fixed set of rules: quote the most similar handbook passage, call the tool when asked about leave balance. It exists because:

  • 開發時不花錢：搜尋、工具、重試這些流程，用假模型就能測。
  • 結果可重現：真的 AI 每次回答可能不同；測試需要固定的結果，才能判斷是不是你的程式壞了。
  • 可以故意犯錯：FakeLLM(mistakes=["fake_citation"]) 會在第一次回答時捏造出處，用來測試第 2 章的重試機制。真的 AI 很難「照指示犯錯」。
  • It's free during development: search, tools and retries can all be tested against it.
  • Results are reproducible: real AI answers vary; tests need fixed results to tell whether your code broke.
  • It can make mistakes on purpose: FakeLLM(mistakes=["fake_citation"]) invents a citation on its first answer, to test chapter I2's retry logic. A real AI is hard to make fail on command.
假模型的極限Limits of the fake

假模型能驗證的是「流程對不對」，不是「回答好不好」。回答品質一定要用真的模型測（第 6 章的 --real）。

The fake verifies that the pipeline works, not that answers are good. Answer quality must be tested with the real model (chapter I6's --real).

The flow is the same as basics chapter B4, now with clear responsibilities. Rules go in the system prompt; handbook passages and the question go in the user message:

為什麼規則放 system、資料放 user？system prompt 是「每一輪都一樣」的部分，固定不變也比較容易被快取（第 5 章）；每一題不同的內容放在使用者訊息裡。

Why rules in system and data in user? The system prompt is the part that's identical every turn, and keeping it fixed makes caching easier (chapter I5); content that changes per question goes in the user message.

小測驗Quiz

1. 為什麼要把 LLM 包成 llm.create(...) 這樣的介面，而不是在 bot 裡直接呼叫 anthropic SDK？1. Why wrap the LLM behind llm.create(...) instead of calling the anthropic SDK directly in the bot?
bot 只依賴介面，不依賴實作，這讓測試與替換都變得容易。
The bot depends on an interface, not an implementation, which makes testing and swapping easy.
2. 假模型的測試全部通過，代表什麼？2. All tests pass against the fake model. What does that tell you?
兩種測試回答不同的問題：假模型測「程式對不對」，真模型測「回答好不好」。
The two kinds of test answer different questions: the fake tests "is the code right", the real model tests "are the answers good".
