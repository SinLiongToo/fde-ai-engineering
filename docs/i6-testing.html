自動測試整個機器人Testing the whole bot

機器人有了搜尋、格式檢查、工具、記憶。每改一個地方，都可能影響其他地方。這一章把入門篇 B5 的「考卷」升級成兩種測試，讓你每次修改後幾秒內就知道有沒有弄壞東西。

The bot now has search, validation, tools and memory, and changing one part can affect the others. This chapter upgrades the B5 "exam" into two kinds of test that tell you within seconds whether a change broke something.

⏱ 20 分鐘min🧪 evals.py · eval_set.jsonl · tests/

這章要加的功能What this chapter adds

  • 單元測試：用 pytest 檢查每個零件（搜尋、格式檢查、工具、迴圈上限）。
  • 評測集：18 題真實問題，逐題檢查四件事。
  • 基準：分數變差就失敗，放進 CI 自動執行。
  • Unit tests: pytest checks each part (search, validation, tools, loop limits).
  • An eval set: 18 realistic questions, each checked four ways.
  • A baseline: fail when the score drops, run automatically in CI.

兩種測試，回答兩種問題Two kinds of test, two questions

單元測試Unit tests

程式的每個零件對不對？Is each part of the code right?

結果固定（用假模型）、跑得很快、每次修改都跑。例如：捏造出處時會不會重試？工具迴圈會不會停？

Deterministic (fake model), fast, run on every change. For example: does a fabricated citation trigger a retry? Does the tool loop stop?

評測Evals

整個機器人回答得好不好？Does the whole bot answer well?

用一組真實問題逐題檢查。用假模型時檢查流程；用真模型時檢查回答品質。

Checks a set of realistic questions one by one. With the fake it checks the pipeline; with the real model it checks answer quality.

評測集：每題檢查四件事The eval set: four checks per question

檢查Check內容What it verifies
搜尋Search相關段落有沒有被找到；手冊沒寫的題目，應該什麼都找不到The relevant passage was found; for not-in-handbook questions, nothing should be found

失敗訊息直接指出是哪一步出問題：這兩題都是「搜尋」沒找到，所以要改的是搜尋（第 3 章），不是 prompt。分開檢查每一步，才知道該修哪裡。

The failure messages point straight at the broken step: both failed at search, so the fix belongs in search (chapter I3), not the prompt. Checking each step separately tells you where to look.

基準與 CIBaseline and CI

確認結果合理後，執行 --update-baseline 把分數存成基準。之後只要分數低於基準，evals.py 就會以失敗結束，CI 會擋下這次修改。這個專案的 GitHub Actions 已經設定好，每次推送都會跑全部測試。

Once the results look right, run --update-baseline to save the score. From then on, a lower score makes evals.py exit with failure and CI blocks the change. This project's GitHub Actions already runs every test on each push.

小測驗Quiz

1. 評測失敗訊息顯示「搜尋：找到 []，應該是 ['H04']」。你應該先改哪裡？1. An eval failure says "search: found [], expected ['H04']". Where should you look first?
分步驟檢查的好處就是能定位問題。沒進 prompt 的段落，模型看不到。
Step-by-step checks locate the problem. A passage that never reaches the prompt is invisible to the model.
2. 為什麼 CI 裡用假模型，而不是每次都用真模型跑評測？2. Why use the fake model in CI instead of the real one every time?
兩者搭配：CI 擋下程式錯誤，定期的真模型評測追蹤回答品質。
Use both: CI catches code bugs, periodic real-model evals track answer quality.
