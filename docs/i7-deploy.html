部署上線：做成別人能用的網站Deploying: a website others can use

到目前為止，機器人只能在你的終端機裡跑。作品集裡如果有一個別人點開就能用的網址，說服力差很多。這一章把機器人做成網站、包成 Docker，部署到雲端，並加上公開網址一定要有的防護。

So far the bot only runs in your terminal. A portfolio piece with a link people can just open is far more convincing. This chapter turns the bot into a website, packages it with Docker, deploys it to the cloud, and adds the protections any public URL needs.

  • 公開網址的防護：每個 IP 的頻率限制、全站每日上限、輸入長度限制、金鑰不進程式。
  • 用 Docker 打包，部署到 Google Cloud Run 或 Hugging Face Spaces。
  • Wrapping the bot as a web page and API with FastAPI.
  • Protections for a public URL: per-IP rate limits, a daily site-wide cap, input length limits, keys kept out of code.
  • Packaging with Docker and deploying to Google Cloud Run or Hugging Face Spaces.

公開網址一定要有的防護Protections every public URL needs

在自己電腦上跑和放到網路上，最大的差別是：任何人都能呼叫它。如果背後接的是付費的 API，有人寫個迴圈一直呼叫，帳單就會失控。

The big difference between running locally and going public is that anyone can call it. If a paid API sits behind it, someone looping requests can run up the bill.

防護Protection這個專案的做法How this project does it
預設不花錢Free by default LLM_BACKEND 預設是 fake。要用 Claude 必須明確設定，而且一定要搭配下面的上限。LLM_BACKEND defaults to fake. Claude must be enabled explicitly, and always with the limits below.
每個 IP 的頻率限制Per-IP rate limit 預設每分鐘 10 次（RATE_LIMIT_PER_MINUTE），超過回傳 HTTP 429。10 per minute by default (RATE_LIMIT_PER_MINUTE); beyond that, HTTP 429.
全站每日上限Daily site-wide cap 預設每天 200 次（DAILY_LIMIT）。這是「最壞情況的帳單上限」：200 次乘上每次的成本（I5）。200 per day by default (DAILY_LIMIT). This is your worst-case bill: 200 × cost per request (I5).
輸入長度Input length 問題最多 300 字，避免有人貼超長文字灌爆 token。Questions capped at 300 characters, so no one can flood tokens with huge pastes.
金鑰不進程式Keys stay out of code ANTHROPIC_API_KEY 只從環境變數讀取，在部署平台設定成 secret。不寫進程式、不寫進 Dockerfile、不推上 GitHub。ANTHROPIC_API_KEY is read only from the environment and set as a platform secret. Never in code, the Dockerfile or GitHub.
不收真實資料No real data 頁面明確告知「手冊是虛構的、請勿輸入個資」。示範版沒有登入，所有訪客都是示範員工 E001。The page says the handbook is fictional and asks for no personal data. There's no login; every visitor is demo employee E001.
這是示範等級的防護Demo-grade protection

限流資料存在記憶體裡，只適用於單一執行個體；平台開了多個執行個體，每個都會各自計算。X-Forwarded-For 也可能被偽造。正式系統要用共用的儲存（例如 Redis）、真正的登入，並在 API 供應商的後台設定花費上限。另外別忘了：真正上線時，user_id 必須來自登入系統（I4）。

Rate-limit state lives in memory, so it only works for a single instance; with several instances each counts separately. X-Forwarded-For can be spoofed. Production needs shared storage (such as Redis), real authentication, and a spending limit set in your API provider's console. And remember: in production, user_id must come from a login system (I4).

那 GitHub Pages、Cloudflare Pages 呢？What about GitHub Pages or Cloudflare Pages?

它們只能放靜態檔案（HTML、CSS、JS），不能執行 Python。這門課的網站就放在 GitHub Pages，但機器人需要伺服器跑 Python，所以要用上面兩種平台。也可以把網頁放在 GitHub Pages、API 放在 Cloud Run，但就要另外處理跨網域（CORS）設定。

They host static files (HTML, CSS, JS) only and can't run Python. This course's site lives on GitHub Pages, but the bot needs a Python server, hence the two platforms above. You could put the page on GitHub Pages and the API on Cloud Run, but then you must handle cross-origin (CORS) settings.

小測驗Quiz

1. 公開網址的機器人接上付費 API，最重要的一道防護是？1. A public bot is wired to a paid API. The most important protection?
放在瀏覽器的金鑰任何人都看得到。防護一定要在伺服器端，並且有最壞情況的上限。
A key in the browser is visible to everyone. Protection must live server-side, with a worst-case ceiling.
2. 為什麼不能把機器人直接放在 GitHub Pages？2. Why can't the bot go straight onto GitHub Pages?
搜尋、呼叫模型、執行工具都需要伺服器端程式，所以要用 Cloud Run、Hugging Face Spaces 這類能跑容器的平台。
Search, model calls and tools need server-side code, so you need a platform that runs containers, such as Cloud Run or Hugging Face Spaces.
